## Inspected success and refusal contracts

- Vite success exposes canonical content and the checksum of the saved document separately. Child
  failure, required package-write failure, empty output, or failed computation does not expose
  `dist`, `pin`, or `manifestChecksum`. The package write precedes computation. On normal return or
  exception unwinding from the execution block, `finally` stops the spinner and awaits command
  cleanup. Default failure handling calls `Deno.exit(1)`, which does not unwind through that
  cleanup. Programmatic callers wanting a failure result must use `exitOnError: false`; other errors
  can still reject. Retained failure summaries explicitly say `Bundle failed`, label the intended
  directory `target:`, and omit manifest links, manifest filenames and content digests; the child
  transcript remains verbatim. Successful summary rendering is unchanged. Failure-cause enhancement
  stays in the later refactor.
- Hash jobs preserve `saveDist: false`; the producer pin exists independently of document
  publication. CLI formatting no longer labels a document checksum as Dist identity. Existing
  document rows distinguish missing, invalid, differing, and saved output.
- Snapshot returns its path/document only after successful saved computation and no longer performs
  a redundant second document write. Its command stops its spinner in `finally` around graph walking
  and computation/save, with success summaries after that boundary. Data mount/root refresh returns
  paths only after success. Slug increments its written count only after successful computation;
  duplicate/missing/non-dir selection behavior is retained.
- Computation selects an inventory; verification checks the complete tree, including rejection of
  symlinks and undeclared entries. Data's `trustChildDist: true` may reuse child inventories without
  rereading their payload bytes. Producer success is not complete-tree verification or independent
  authenticity.
- Empty and unsafe selected inventories refuse before manifest writes and preserve prior document
  bytes. This does not generalize to save failures: computation explicitly makes no rollback promise
  after a failed save. Positive controls verify saved output using public Local/Pinned verification;
  they do not turn locally produced metadata into independent trust.
- The cached Serve fixture's canonical hash is recomputed from the actual fixture bytes. The serve
  child retains its existing restricted authority and does not acquire build authority.
