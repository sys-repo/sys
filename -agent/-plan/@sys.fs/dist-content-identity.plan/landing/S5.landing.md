## Contract inspection and bounded corrections

- Pull YAML requires `pin: { scheme, digest }`. Shared `Pkg.Is.distPin` owns pin semantics; the YAML
  schema locates errors without inventing a second digest grammar. Old-only and mixed `integrity`
  inputs refuse. CLI parsing rejects the old flag and refuses add-only flags outside `add` before
  acquiring the selected configuration. No conversion, inferred pin, or checksum alias was added.
- Add/config persistence retains the independently supplied pin. Interactive entry explicitly names
  the sole content scheme and asks for the external digest; it does not obtain authority by hashing
  a download. Help, summaries, idempotence comparisons, and fixtures use the same contract.
- Materialization forwards `bundle.pin` to Server and projects only a successful generation's
  admitted `content.parts`. Mutable projection and HTML rewriting never inherit verification.
  Existing source-origin/credential restrictions, finite budgets, cancellation, target isolation,
  real lease coordination, and cleanup order remain. A wrong pin produces manifest-admission
  refusal; the public-run test now also proves one manifest request and no payload/projection
  acquisition.
- Two added public `Pull.run` cases put a valid bundle before an old-only or mixed bundle. Both
  refuse the whole configuration with zero fixture requests, no store/projection creation, and
  unchanged YAML. Existing successful materialization, sealed generation/mutable projection, warm
  reuse without refetch, config stability, cancellation, and GitHub routing controls remain.
- The existing projection race test polled Fs's private stage-directory layout. It now wraps a real
  public Rooted instance through a Tools-internal factory seam and observes the public projection
  `Lease.acquire` call after staging. The test retains its separately held real lease, creates a
  winner before releasing that lease, and checks unchanged winner bytes/modes. `Time.waitFor` owns
  bounded observation. No private Fs import, layout name, or new Fs API is involved; production uses
  the same public factory by default. The race is exercised at the post-staging/pre-lease-settlement
  boundary rather than by discovering private files.
- Serve's optional status details observe canonical manifest metadata only. Static Serve remains
  unpinned and does not become verified Dist hosting. Added controls show legacy metadata
  contributes no details while ordinary static bytes remain servable, and changed payload bytes can
  be served alongside unchanged canonical metadata. The comment now states this boundary explicitly.
  The canonical fixture descriptors/digests are valid; displayed build sizes/times remain
  descriptive metadata, not measured or authenticated payload facts.

The public Pull module documentation now says payloads are verified against a pin, not that the pin
itself is authenticated. These corrections do not reopen S4 or migrate build producers.

Adjudication preserves the architecture and accepts the following bounded corrections:

1. **URL preflight — accepted correctness obligation.** YAML's permissive HTTP(S) prefix pattern
   admitted malformed or userinfo-bearing URLs until each bundle executed. Schema admission now uses
   `Is.urlString` and `Url.parse` plus the same no-userinfo rule before dispatch. Shared
   `Pkg.Is.distPin` still owns pin semantics; field diagnostics locate both kinds of refusal. Public
   `Pull.run` cases put each invalid URL second, after a valid bundle configured to replace an
   existing projection. They require configuration refusal, zero fixture requests, no store,
   unchanged configuration and existing output, and no acquired asset. A two-valid-bundle control
   materializes both, reuses the sealed generation, and preserves YAML. A narrow schema test covers
   malformed HTTP/HTTPS URLs and username/password variants with exact field diagnostics.
2. **README identity and rejected example — accepted.** The package README now describes the
   independent `{ scheme, digest }` pin, payload identity versus exact-document checksum, and root
   metadata/serialization exclusions. Its command uses `--scheme sys.dist/v2 --digest`, not the
   rejected `--integrity` flag. Existing sealing limitations remain explicit.
3. **Projection consequences and path anchor — accepted.** README, Pull help/add help, and public
   configuration types explain occupied-target refusal, destructive replacement without rollback,
   HTML rewriting without inherited verification, and the two-level YAML-directory anchor. They
   identify the standard layout, resolution through YAML `dir`, and relocation consequences. Help
   assertions cover both general and add help.
4. **Serve observation caveat — accepted.** README, the public Serve module, and CLI help now state
   that displayed Dist metadata does not authenticate served bytes and build size/time are
   descriptive. A focused help test pins that operator explanation; existing static-payload controls
   remain. No serving policy changed.
5. **Audience and sealing terminology — accepted.** Generic Pull help no longer carries Cell
   descriptor migration guidance; Cell's authored pulled-view chapter already owns that rule and was
   not changed. Interactive Pull and this receipt say sealed, not immutable.
6. **Summary identity assertion — accepted non-blocking proof improvement.** The distinct-fixture
   content pin must appear in the summary, while its manifest checksum must not.
7. **Race evidence — accepted qualification and bounded proof improvement.** The test captures a
   real public `Stage` handle, checks staged payload bytes at the lease-call boundary, and asserts
   its path is absent after settlement but before broad fixture cleanup. Teardown now cancels,
   releases the held lease, and drains pending work; early rejection has an observer without
   replacing the original awaited outcome. This proves winner preservation at the public
   post-staging/pre-lease-settlement boundary. It does **not** independently establish which
   internal lock-contention branch ran, or impose a hard bound on all teardown I/O. No private Fs
   layout discovery, hooks, or new capability exports were added.

## Shared-add follow-up — bounded TMIND correction

A subsequent human-supplied factoring review identified behavioral drift between interactive
addition and `addDistBundle`: duplicate projections were rejected before deduplication, and the
interactive YAML writer skipped final schema admission. The human authorized this correction and
adjacent bounded cleanup, not the optional formatter or projection extractions.

In-thread adversarial inspection followed operator idempotence, mutation admission, and stale-menu
state. The strongest reason to retain the design was that the existing durable add operation already
owned the required behavior; another persistence abstraction was unnecessary.

- Interactive prompts now collect input and delegate to `addDistBundle`. Duplicate equality,
  isolation, current-document loading, YAML validation, and no-op/write decisions have one owner.
  Removed the interactive YAML writer, duplicate equality helper, and snapshot-based add isolation.
- Manifest and relative-path field parsers are shared with prompt feedback. They are internal Tools
  implementation exports, not additions to the public Pull library or another package's surface. Raw
  mode strings are narrowed by the add owner; the UI no longer casts them as admitted modes.
- The internal prompt seam substitutes only text/selection effects. Production defaults to the
  existing frozen Cli input surface. Its selection port accepts raw string choices, without exposing
  the backend's generic widening type or weakening any admission check.
- Parity tests cover successful addition without materialization, exact and equivalent duplicates
  with/without projection, byte-preserving no-op behavior including comments, invalid pins, final
  schema refusal, unsupported modes, and config changes during prompts. The latter check the
  document loaded for mutation, not the old menu snapshot. This is not concurrent-writer locking or
  compare-and-swap proof during the later read/write interval.
- Residue cleanup names the used `cwd` parameter honestly, uses `Is.array` for the adjacent asset
  guard, and removes stale imports/types and redundant mode assertions. No formatter hierarchy,
  projection extraction, Fs API change, or general YAML transaction redesign was added.
