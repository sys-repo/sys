## Inspected contract and regression coverage

- `ReadRoute.fromDist` captures the independent `{ scheme: 'sys.dist/v2', digest }` pin, storage
  source, callbacks and explicit limits before acquisition. Legacy `integrity`, mixed inputs and
  invalid pins refuse rather than becoming aliases. Bounded manifest acquisition feeds the shared
  `Pinned.admitManifest` owner; route policy receives only immutable admitted content, not root
  package/build observations. Tests cover legacy/unsupported input, substitution, limits,
  metadata/layout invariance and zero policy calls on refusal.
- Storage signing/fetching of the manifest necessarily precedes inventory admission. Route policy
  does not. Existing allowlists, authorization, cancellation and timeout behavior remain: the read
  deadline covers signing/acquisition, not later verification/policy. Cancellation can settle the
  public call before pending work; the worker retains its abort listener and disposes the read
  operation after read/body cleanup. Lifecycle tests exercise cancellation, timeout, late work and
  captured authority. This is not a promise to drain every operation before returning refusal.
- Sample build consumes the builder's content pin, refuses producer failure, projects private and
  public inventories, and records each projection's own pin. Bundle size comes from admitted part
  sizes rather than descriptive build metadata. Fixtures narrow successful producer results before
  using their pins. Deterministic tests exercise these contracts without running a real Vite build.
- `selectBuild` captures the pin and retains the first verified `manifestChecksum` for subsequent
  checks. Equal content does not reset that document fence. `prepareProof` compares captured
  manifest bytes with that checksum and payload bytes with admitted part checksums, then rechecks
  the original selection. Proof reports keep `pin` and `manifestChecksum` separate. Tests include
  same-content document replacement during expectation capture and later proof phases.
- Publication admission verifies both recorded audience pins and filename policies before either
  audience is selected for publication. Existing push behavior publishes the selected build rather
  than rebuilding or repinning it. Missing partners, stale pins and forbidden filenames refuse; old
  build records receive rebuild guidance rather than conversion. Provider mutation/acceptance was
  not exercised in this pass.
- Status uses verified content identity. Browser manifest fetching remains observation only:
  reported digest and payload size are distinct from the checksum of the exact downloaded document.
  Render/load tests cover separate origins, independent completion/failure and disposal. Neither
  this UI nor construction-time R2 admission verifies subsequent payload delivery or browser
  execution. Serving `dist.json` later need not reproduce the construction snapshot.
