## Accepted corrections

### R2-A01 — P2: enforce structural entry authority at Generation settlement

Source: report `01-fs-server.review.md`, finding 1.

Owner: `code/sys/server/src/m.server.dist/u.generation/u.is.ts::isVerification`.

**Accept.** The comparison uses `assets.files`, then checks that it matches the inventory's file
count. It never adds `dist.json` or distinct implied directories. FS
`code/sys/fs/src/m.Pkg.Dist/u.verify/u.manifest.ts::assertEntryLimit` does both. Its public limit
contract agrees. The existing Generation budget matrix covers path length, aggregate path units, and
repeated-prefix work, not structural entries.

A genuine three-file/one-directory result obtained under a sufficient policy can therefore pass
outer settlement with `entries: 4`, although FS requires five structural entries. The ordinary
production materializer still performs FS admission; this is independent settlement of lower
evidence under narrower caller authority, not an established ordinary-download bypass.

**Correction:** count the manifest, admitted payload paths, and distinct implied directories under
the effective FS entry ceiling. Charge repeated-prefix work before allocating directory strings;
shared directories count once for entries but every prefix visit counts for work. Preserve digest,
size, seal, source, and transfer checks. No second filesystem verification pass.

**Closure:** genuine lower-result replay at four/five entries; a root-only payload at one/two;
shared-directory controls; compare FS admission/verification and actual materialization. Refusal
returns no owner and releases exactly once; failed release remains pending. Sufficient controls open
and retain ownership until explicit release.

### R2-A02 — P2: capture direct-materialization policy before lifecycle execution

Source: report `01-fs-server.review.md`, finding 2.

Owner: `code/sys/server/src/m.server.dist/u.materialize/u.input.ts::snapshotInput`.

**Accept.** `Is.untilInput(until)` runs before `snapshotPolicy(input.policy)`. The Std predicate
reaches ordinary lifecycle `disposed`, `dispose$`, or observable properties, which can execute
getters. A getter can replace the original entry limit before it is owned. Capturing before the
first await alone is insufficient. The pin is already copied correctly; Generation's separate
ordering is also not evidence that this direct entry point is correct.

**Correction:** capture all non-lifecycle policy authority before lifecycle observation. Preserve
input-versus-policy failure distinctions and intentional failure precedence. Do not reject all
supported lifecycle views or introduce a generic snapshot framework to avoid the ordering issue.

**Closure:** direct public materialization with tight-to-wide and wide-to-tight getter mutations,
unchanged controls, captured-policy assertions, and actual acquisition/refusal assertions. Include
both nested-pin mutation directions at direct materialization and Generation: the originally wrong
pin must not become matching, and the originally matching pin must remain the governing pin.
Post-invocation mutation tests do not replace these synchronous getter controls.

### R2-A03 — P2: retain the original copy error when residue inspection fails

Source: report `02-tools.review.md`, material finding.

Owner: `code/sys.tools/src/cli.deploy/u.staging/u.copyInto.ts::rethrowCopyFailure`.

**Accept.** The first `await Fs.lstat(target)` is outside the retention `try`. The FS helper
suppresses only `NotFound`; another rejection replaces the original copy failure before the
aggregation branch. Both thrown and returned copy failures reach this path. The existing symlink
controls fail later, inside `stagingManifestChecksum`, and do not test this first observation.

**Correction:** include initial manifest-residue observation in the protected retention operation.
Missing residue still means no record. Keep the final original-error throw outside that operation so
it cannot be caught and aggregated with itself. Ordinary payload failures remain outside the
manifest ledger.

**Closure:** through the existing copy seam, reach initial observation failure after thrown and
returned copy errors. Assert one production-argument copy call, original identity at
`AggregateError.errors[0]` and `cause`, inspection error second, an empty ledger, and preservation
of replacement/displaced bytes after rollback. Verify the host's actual filesystem error
classification; the proposed non-directory-parent sequence is not yet an executed reproduction. Do
not use permission denial or a global monkey-patch as fault injection. Preserve regular-residue,
symlink, absent-residue, and ordinary-payload controls.

### R2-A04 — P2: make the Dist observation guard honest about its returned type

Source: report `04-observation-docs.review.md`, F1. **Accept defect; revise P1 to P2.**

Owner: `code/sys/std/src/m.Pkg/m/m.Is.ts::PkgIs.dist` and `wrangle.distBase`.

The guard validates the descriptor and some build metadata, but not required `build.size`, its
numeric members, `time`, `builder`, or `runtime`. `DistPkg` promises those fields. The hook
publishes that narrowed object, and the actual ModuleList Title consumer dereferences
`dist.build.size.total`. An otherwise supported JSON document missing `build.size`, or containing
null there, reaches an unguarded dereference. This is not hypothetical reliance on an unused type.

The demonstrated consequence is malformed-observation render failure, not content-pin bypass,
execution of unauthenticated payload, or a demonstrated broad production outage. P2 is the supported
severity; it remains a required correction before this landing.

**Correction:** complete required structural checks at the existing Std guard. Keep root `pkg`
optional. Do not add digest recomputation, make descriptive metadata part of identity, or tighten FS
pinned admission to require descriptive build fields. Shape recognition and authenticated inventory
admission intentionally have different contracts.

**Closure:** otherwise valid descriptors with omitted/null/array/wrong-scalar required build
members; valid controls with and without `pkg`; hook refusal with bounded error and no typed JSON; a
narrow consumer-boundary no-crash proof. Keep the HttpOrigin control that accepts a syntactically
valid but forged declared digest as an explicitly unpinned observation. No sample App markup/style
changes.

### R2-A05 — P2: distinguish actual sample data from permission to use fallback

Source: report `04-observation-docs.review.md`, F2.

Owner: `code/sys.ui/ui-react/src/use/use.Dist/use.Dist.ts`.

**Accept.** `is.sample` is always the option `sampleFallback`; neither remote success nor sample
settlement changes it. Remote data with fallback allowed is mislabeled. Disabling fallback can also
expose retained sample JSON with `is.sample: false` before the replacement effect clears it. The
current tests use the same data for remote/sample and never assert this flag or change options.

**Correction:** derive the flag from actual observation source, keeping source/JSON/error coherent.
Use `sampleFallback` only as input policy and effect dependency. Preserve the failed remote
attempt's error when sample fallback is displayed. Retain cancellation and post-await disposal
checks; do not add an independent pin or a general trust-state API.

**Closure:** distinguishable remote/sample fixtures; valid remote with fallback enabled; malformed
success and rejected transport with fallback enabled/disabled; option changes with delayed old/new
completions, including render-time state; no late transport or sample settlement after disposal.
