## 2. Material finding

### F1 — P1: capture the pin before lifecycle getters can retarget it

**Owner and anchors**

- `code/sys/fs/src/m.Pkg.Dist/u.verify/u.verify.ts::admitPinnedArgs`, lines 198–206: calls `admitBaseArgs(values)` before `snapshotPin(values.pin)`.
- The same file, `admitBaseArgs`, line 236: calls `snapshotUntilInput(until)`.
- `code/sys/fs/src/m.Pkg.Dist/u.verify/u.input.ts::snapshotExactDataObject`: copies top-level property values, not nested pin contents.
- `code/sys/fs/src/m.Pkg.Dist/u.verify/u.input.ts::snapshotUntilInput` → `isUntilSnapshot` → `Is.untilInput`.
- `code/sys/std/src/m.Is/m.Is.ts::lifecycleView`, lines 73–81: reads `view.disposed` and `view.dispose$`; these can be valid getters.

**Executable failure sequence**

1. Prepare a valid Dist B using the existing `setup()` fixture.
2. Pass a mutable, structurally valid pin whose digest is A, different from B.
3. Supply a valid live lifecycle view whose `disposed` getter assigns B's digest into that same pin.
4. `admitBaseArgs` invokes the getter while the top-level snapshot still holds the caller's pin object.
5. `snapshotPin` subsequently copies B, and the verifier admits and reads B. Source-derived result: `verified`, although the invocation supplied A. With correct capture, the result is `pin-mismatch`, with neither tree traversal nor payload acquisition.

The following regression can be inserted into the existing `code/sys/fs/src/m.Pkg.Dist/-test/-input.admission.test.ts`; it uses that file's existing imports. It was not executed during this review:

```ts
it('Pinned.verify captures its pin before lifecycle getters run', async () => {
  const fixture = await setup();
  const life = Rx.lifecycle();
  const pin = { ...fixture.pin, digest: Hash.sha256('not-the-selected-dist') };
  const calls: IoCall[] = [];
  let getters = 0;
  const until = {
    get disposed() {
      getters++;
      pin.digest = fixture.pin.digest;
      return life.disposed;
    },
    get dispose$() {
      return life.dispose$;
    },
  };
  try {
    const result = await verifyPinnedWithIo(
      { dir: fixture.dir, pin, limits, until },
      traceIo(calls),
    );
    expect(getters).to.be.greaterThan(0);
    expect(result).to.eql({ kind: 'pin-mismatch' });
    expect(calls.filter((call) => call.operation === 'readDir')).to.eql([]);
    expect(calls.filter((call) => call.operation === 'open').map((call) => call.path))
      .to.eql([StdPath.join(fixture.dir, 'dist.json')]);
  } finally {
    life.dispose();
    await Fs.remove(fixture.dir);
  }
});
```

**Violated invariant:** independent expected authority must be captured before executable caller hooks run. This is not merely post-return caller mutation, and it does not require a hostile filesystem or hash collision. It requires a shared mutable pin and a getter-bearing lifecycle view, both accepted input patterns. A caller that supplies only frozen pins and native signals will not encounter this sequence.

**Attribution:** the previous `integrity` expectation was a primitive string already copied by the top-level snapshot. Replacing it with a nested object while retaining the old sequencing introduces the gap. Readonly TypeScript fields do not freeze a caller's runtime object.

**Smallest correction:** in `admitPinnedArgs`, snapshot and validate `values.pin` immediately after the top-level data snapshot, before calling `admitBaseArgs`. Preserve the existing root/limits capture before lifecycle validation. No new abstraction, global lifecycle change, or permission expansion is necessary.

This ordering is already correctly explicit in:

- `u.verify/u.admitManifest.input.ts::snapshotManifestArgs` — pin, limits, owned bytes, then lifecycle;
- `u/u.project.ts::captureInput` — source pin and other data before `batchUntil`;
- `m.Pins.ts::verifyPinsWithIo` — selection pins/directories/limits before `batchUntil`.

**Closing proof:** run the regression above; also reverse the mutation (initially matching pin changed to a different digest) and require successful verification against the original expectation. Keep the existing proxy/accessor, CWD-capture, pre-ended lifecycle, and no-payload-before-pin tests passing. After the test is added, the exact narrow command is:

```sh
cd /Users/phil/code/org.sys/sys/code/sys/fs && deno task test:unit --frozen --cached-only --trace-leaks ./src/m.Pkg.Dist/-test/-input.admission.test.ts
```

### Admission details checked

- The sole encoder is `code/sys/std/src/m.Pkg/m/m.Dist.Content.ts`: UTF-16 code-unit ordering, compact native JSON, required canonical SHA-256 and byte length, scalar strings, no normalization, package slot, or trailing newline.
- FS imposes 16 MiB manifest bytes, the Content entry/path ceilings, safe-integer arithmetic, and separately charges every implied-directory prefix before allocating it. Rooted remains the lexical/structural path owner.
- One leading BOM is accepted by the decoder; malformed UTF-8, double BOM, malformed JSON, old/missing/unknown schemes, forged self-reported digests, missing lengths and empty inventories refuse.
- Duplicate and escaped-equivalent JSON members deliberately use the native parser's final member. There is no second security interpretation or traversal of excluded extension metadata.
- Portable/reserved paths, structural conflicts and spelling repairs refuse; prototype-sensitive own keys and leading-space names survive. Exact inventories—not ignore rules—govern verification.
- `u.verify/u.tree.ts::readRegularFile` checks metadata before/open/after, exact size, bounded allocation and reads, an EOF probe, root continuity, and closes the handle before settlement. Second-observation transitions remain `changed`; missing stable identity remains `unsupported`.
- Cancellation is cooperative. Native reads are awaited, not abandoned in a race with an abort promise. Manifest-only admission yields before checking a pre-ended lifecycle. No claim is made that parsing or native IO has a hard cancellation deadline.

## 6. Owner boundaries and optional simplifications

Retain the current owner split:

1. **Std Content** defines portable deterministic encoding and finite pure-work ceilings; it must not absorb filesystem policy or crypto authority.
2. **FS admission** binds the descriptor to Rooted's portable path grammar, graph/byte limits and cryptographic recomputation. Sharing this owner between compute, load, manifest-only and whole-tree admission prevents alternate algorithms.
3. **FS tree IO** owns bounded reads, observed identity/change classification and resource settlement.
4. **Projection/Pins coordinators** own enclosing-operation ordering, aggregate budgets, source document fences and partial-output truth.
5. **Rooted** owns cooperative target publication and safe cleanup. A content pin is neither deletion authority nor publication provenance.

The new content descriptor, exact two-field pin, immutable evidence projection and explicitly named manifest checksum each have a distinct necessary responsibility. Removing deep copying of descriptive metadata is a genuine simplification and reduces pre-authentication work; it is not loss of authenticated evidence. Reusing the old verifier behind Local would be the wrong simplification.

Nonblocking reductions:

- `code/sys/fs/src/m.Pkg.Dist/u/u.hash.ts::bytes` (line 65) has no remaining caller in this module after totals moved to admitted sized parts. Remove the dead helper rather than preserve a second totals path.
- The child-merge branch at `u/u.hash.ts:48` computes `CompositeHash.digest(outParts)` although `compute` consumes only `collected.parts` and computes the sole Dist digest through `captureContent`. Returning a private parts-only result would remove this redundant generic digest and its import from this helper. Do not change Crypto's generic digest contract or remove the generic/Dist domain-separation test.
- `u.verify/common.ts` still re-exports `CompositeHash` and `Ignore`, although the new verification helpers no longer use those authorities. Trimming dead exports would better express the clean break, without inventing another barrel layer.

Documentation now leads with the important distinction between local consistency, independent content identity and exact-document continuity. The README's Rooted section also correctly limits directory no-clobber to cooperating callers. Keep those limits visible rather than describing these observational checks as containment.
