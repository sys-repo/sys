## Finding ledger

### A01 — P1: capture the FS pin before lifecycle hooks

**Accepted. Source:** report 02 F1. **Owner:** FS. **Attribution:** replacement regression.

`code/sys/fs/src/m.Pkg.Dist/u.verify/u.verify.ts::admitPinnedArgs` calls `admitBaseArgs` before
`snapshotPin`. The top-level `snapshotExactDataObject` in `u.verify/u.input.ts` copies the nested
pin reference, not its fields. Base admission calls `snapshotUntilInput`; Std's
`code/sys/std/src/m.Is/m.Is.ts::{untilInput,until,lifecycleView}` reads valid lifecycle getters.

A mutable initial pin A plus a lifecycle getter assigning valid candidate B's digest is consequently
captured as B. Predicted result: verification of B instead of refusal against A. The old primitive
`integrity` was already copied by the top-level snapshot; reachable HEAD confirms that distinction.
This is a same-process input-ownership defect requiring shared mutable input and executable
lifecycle behavior, not remote digest forgery. Retain P1 because the selected expectation itself can
change.

**Correction:** snapshot/validate the pin immediately after top-level capture, before base lifecycle
validation. Keep existing limits/root capture and lifecycle behavior; no global guard redesign.

**Closing proof:** in `code/sys/fs/src/m.Pkg.Dist/-test/-input.admission.test.ts`, test both
mutation directions. Initial wrong → getter changes to matching must remain `pin-mismatch`, with no
tree or payload acquisition. Initial matching → getter changes to wrong must verify the original
pin. Retain proxy/accessor, CWD, pre-ended lifecycle and manifest-only input tests. New regressions
are unexecuted.

**Closing proof:** extend `code/sys/server/src/m.server.dist/-test/-generation.authority.test.ts`

### A04 — P2: preserve the current document fence through finalizer hashing

**Accepted as an inherited defect, not a v2 regression. Source:** report 04 F2. **Owner:** Tools
staging. Integration/scope approval remains human-owned.

`code/sys.tools/src/cli.deploy/u.staging/u.finalizeDistTree.ts::writeManifest` validates the
retained current document, or its absence, before awaiting compute. After compute it checks
directory identity and child manifests, but force-writes its own manifest without repeating the
current-document check. The ledger is then replaced with the new checksum. Reachable HEAD has the
same ordering.

A synchronous hash-progress hook can replace M with metadata-only M′ after initial validation.
`code/sys/fs/src/m.Pkg.Dist/u/u.hash.ts::includeHashPart` excludes `dist.json`; computation does not
notice the change. M′ can be overwritten and its lost ownership hidden by a new ledger record. The
initially-absent → newly-appeared-document case has the same gap. Both sequences are source-derived,
not executed here.

**Correction:** revalidate the originally retained record, or original absence, after hashing and
immediately before writing. Never recapture M′ as the new baseline. On refusal, retain the original
ledger so cleanup preserves changed bytes and reports its separate failure. This closes the named
observation gap, not every pathname race or an atomic compare-and-swap guarantee.

**Closing proof:** add both hashing-phase cases to
`code/sys.tools/src/cli.deploy/u.staging/-test/-u.execute.test.ts`; assert preserved replacement
bytes, no ledger renewal and truthful body/cleanup failure. Pair with unchanged-document success.
Keep existing post-write root/child replacement tests: they exercise a different phase.

This satisfies the current plan's explicit enclosing finalization/document-ownership invariant if
the human approves its inclusion. It does not reopen the separate R2 publication repair, authorize a
new arc item, or retroactively relabel an inherited bug as introduced by Dist v2.

### A05 — P2: a required Vite package write cannot yield successful build authority

**Accepted as an inherited defect, not a v2 regression. Source:** report 06 F1. **Owner:** Vite.
Integration/scope approval remains human-owned.

`code/sys.driver/driver-vite/src/m.vite/u/u.build.ts::build` ignores the result of writing
`pkg/-pkg.json`. `code/sys/fs/src/m.Fs/u/u.write.ts::write` returns errors by default. Vite proceeds
to compute/save Dist and can return `ok: true`. Reachable HEAD confirms the unchecked write predates
this replacement.

parent is asked to write B. If that write fails but manifest production succeeds, the returned pin
correctly commits A, not the requested output B. Correct Pi package checks reject it; hashing is not
broken. The real filesystem sequence and deterministic injected-error alternative are unexecuted.

**Correction:** inspect the required write result and use Vite's existing failure branch before Dist
computation/publication. Do not add a universal package declaration requirement to FS, infer package
identity from root labels, or change generic no-package builds.

**Closing proof:** strengthen `code/sys.driver/driver-vite/src/m.vite/-test/-build.test.ts` with
exact own declaration membership and decoded package equality. Add a
successful-child/failed-parent-write control requiring `ok: false`, no
`dist`/`pin`/`manifestChecksum`, and no newly successful manifest write. Do not claim that prior
child output was rolled back. Use a Vite-owned fixture and existing authority; a real read-only-file
test is host-sensitive and must restore fixture-owned modes safely.
